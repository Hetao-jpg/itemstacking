面向 API 的优化建议
一、契约层（隔离游戏内部细节）
1. 私有字段直读 → 统一 Accessor

text
GameItemAccessor.State(item)      // 封装 _state_k__BackingField
TagStateAccessor.Fields(ts)       // 封装 valueEnabled/valueInt/...
现状：StateConsistency.cs 直接点字段，游戏改版 = AccessViolation。
API 化后：解析失败 → 返回 null + 一次性告警，退化为「状态不可比 → Deny」。

2. SameInventory / SameNativePtr 合并为一个 API

text
GameRef.Same(a, b)   // 内部统一 Pointer 比较，null 安全
现状：两套指针比较语义重复，AltPairTransfer 用一套、StackGates 用一套。

3. 探针 API 统一门控

text
Probe.Run(() => { DumpCounterProbeOnce(...); ProbeScopeInventory(...); });
现状：调用点逐个 if (DiagOn)，且实参（闭包）仍急切求值。API 化后一处门控，实参延迟。

二、决策层
4. 判据注册表 API

text
MergeRule { Name, Priority, Group, Judge(ctx) → reason? }
rules.Register(new ContainerRule());
rules.Register(new StateRule());   // 顺序由 Priority 定
现状：Evaluate 里 if-else 硬编码顺序，新增判据要改框架。API 化后规则可单测、可禁用、可重排。

5. MergeContext 显式携带权威容器

text
MergeContext.Build(slotInv, target, source)   // slotInv 必填
现状：slotInventory 与 target.parentInventory 两个来源，注释说"以 slotInv 为准"但代码里有 fallback。API 化后构造时断言唯一来源。

6. Evaluate 结果缓存 API

text
EvalCache.Get(ctx)   // key = (target, source, slotInv, frame)
依据：注释已声明「三挂点结论必然一致」，缓存与该声明同源。

7. 回滚路径 API 化

text
IMergePolicy { Evaluate(ctx) }
LegacyPolicy / SingleSourcePolicy   // cfg 选择实现
现状：UseMergePolicy=false 让 0.9.9 内联判据与新路径在同一函数里并存。API 化后两条路径互不污染，删旧路径 = 删一个实现类。

三、覆盖层（黑白名单/忽略名单）
8. 名单覆盖统一为泛型 API

text
Overlay<string[]>.Load(doc, key, ref target, ref source)
现状：LoadBuiltinBlacklist 与 LoadIgnoredStateTags 各自实现「代码默认 + JSON 覆盖 + 来源标签」。API 化后一处。

9. 容器 token 匹配抽为独立 API

text
ContainerMatcher.Match(inv, token)   // 裸 id / slot: / owner: 三分支
ContainerMatcher.Describe(inv)       // 探针/拒绝原因共用
现状：MatchesContainerToken / IsContainerInList / BriefContainer / DescribeContainer 逻辑交织。

四、机器/销毁修复
10. 拆堆-归还泛型化

text
SplitStackFix.Apply<TArgs>(args, itemSelector, splitTag)
现状：UpgradePrinter / RestoreModule / RepairExtractor / 熔炉 / 解序器 五处结构重复，仅参数名不同。

11. 原生尾部复刻 API 化

text
NativeContract.AltHandlerTail(handler)   // ResetAfter + currentItem=null + key-up
现状：NativeTailCleanup 在 AltPairTransfer 内联，是隐式契约（游戏改尾部 = 失配）。API 化后一处 + 一处自检。

五、自检层
12. 自检注册表 API

text
SelfCheck.Register(label, () => AccessTools.Method(...) != null);
SelfCheck.RegisterMember(label, () => FieldExists(...));
SelfCheck.RunAll();
现状：ValidatePatches 顺序罗列 40+ 条 Check(...)，新增自检需手写。API 化后自检模块与补丁同文件注册。

13. 版本号单一源

text
BuildInfo.Version   // AssemblyInfo 与 cfg 默认值读同一常量
现状：AssemblyInfo = 0.11.2，注释写 1.0.0，cfg 说明可能又一版。

六、性能 API
14. FindAllChildItems 帧级缓存

text
ItemQuery.Children(item)   // 内部按 (Ptr, frame) memo
理由：IsContainer 一次拖放被调 6 次，每次都深遍历。

15. MatchEmporiumSlot 快照缓存

text
EmporiumSnapshot.Slots()   // 按 EmporiumEntry.Instance 指针失效
理由：每次合并 8 次 getter，可缓成一 struct。

优先级
| P0 | 1、2、3、14 | 直接影响稳定性 / 性能 |
| P1 | 4、5、12、13 | 后续扩展的基础 |
| P2 | 6、8、9、10、11、15 | 减重复，降维护成本 |
| P3 | 7 | 等 1.0.0 稳定后再做 |
